\title{Condition-Aware Selective Abstention for Bias Benchmark Question Answering: A Multi-Signal Audit of BBQ Condition Separability}

\author{\uppercase{Mose Kim}\authorrefmark{1}, \uppercase{Suhyun Kwon}\authorrefmark{2}}

\address[1]{Department of Electronic Engineering, Tech University of Korea, Siheung, Republic of Korea}
\address[2]{Department of Embedded Systems, Tech University of Korea, Siheung, Republic of Korea (e-mail: tngus0729@tukorea.ac.kr)}

\corresp{Corresponding author: Mose Kim (e-mail: mose712@tukorea.ac.kr).}

\begin{abstract}
Bias-sensitive question answering requires context-dependent behavior: ambiguous contexts call for an unknown answer, while disambiguated contexts call for evidence-based answers. We introduce and audit \method{}, a frozen-model inference-time policy for Bias Benchmark for Question Answering (BBQ)-style multiple-choice question answering that predicts whether each instance is ambiguous or disambiguated and then applies condition-specific abstention without oracle condition labels at test time. The central finding is that the original BBQ split is highly condition-separable. An embedding-only classifier using no answer choices, metadata, model outputs, or extracted signals predicts the ambiguous/disambiguated boundary with 0.9961 test accuracy (0.887 when train and test share no BBQ template, where the retention policy itself degrades to 0.932 ambiguous accuracy and 0.148 false abstention), and lexical n-gram plus encoder-sensitivity audits confirm that the boundary is recoverable across simple text features and alternative sentence encoders; even a three-feature context-length classifier reaches 0.948, reflecting that disambiguated contexts append a sentence to ambiguous ones by construction. Consequently, a simple predicted-condition retention rule achieves 1.0000 ambiguous accuracy, 0.8789 disambiguated accuracy, and 0.0726 false-abstention rate (FAR) on the clean split. A seven-signal, condition-aware mixture-of-experts (MoE) retention variant using evidence, stability, confidence, self-consistency, prompt sensitivity, attention, and sparse-autoencoder features does not improve this clean-split frontier, achieving 0.9946 ($\accamb$), 0.8732 ($\accdis$), and 0.0843 ($\far$) on the same metrics. We interpret this negative MoE result as a structural benchmark finding: clean BBQ rewards condition-aware selective abstention more than fine-grained multi-signal retention. The multi-signal layer remains useful under scarce condition supervision, especially at 1--5\% label fractions. We add deterministic rule-based decision explanations and signal-based bias-risk explanations, then probe the finding's boundaries with Leave-One-Category-Out (LOCO) category holdout, Open-BBQ transfer, KoBBQ condition- and end-to-end transfer, Qwen/Mistral cross-LLM, condition-aware risk-control, deterministic paraphrase-stress, and evidence-verification audits; transfer to implicit-cue paraphrases and cross-lingual deployment degrades substantially, which we report explicitly as boundary conditions. The contribution is an audit of BBQ condition separability, not a causal claim about debiasing mechanisms.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
\IEEEPARstart{L}{arge} language models (LLMs) are increasingly used as general-purpose question-answering systems, including in settings where user queries contain demographic attributes or socially sensitive contexts. Bias evaluation for question answering is difficult because the desired behavior changes with context. In the Bias Benchmark for Question Answering (BBQ) \cite{parrish2022bbq}, ambiguous contexts should usually lead to an unknown answer, while disambiguated contexts should allow the model to answer from the evidence. A debiasing method that always abstains may appear safe on ambiguous items but can sharply reduce utility on disambiguated items. Conversely, a method that preserves utility can still propagate stereotypes when the context does not identify the correct answer.

This paper frames bias mitigation in BBQ-style question answering as a condition-aware abstention problem. Instead of changing model weights, we keep the base model frozen and ask whether a deployable system can decide when to preserve the model's original answer and when to override it to the unknown option. The central component is a condition predictor that estimates whether an instance is ambiguous or disambiguated without using oracle condition labels at test time. We then audit a multi-signal retention model that combines surface evidence checks, counterfactual stability, log-probability confidence, self-consistency, prompt sensitivity, bias-head attention, and sparse-autoencoder (SAE) feature activation. Finally, we attach a rule-based explanation layer that states whether a decision abstained because the context was predicted ambiguous, preserved utility in a predicted-disambiguated context, blocked a raw answer that was stereotyped under the BBQ metadata, or triggered a signal-based bias-risk explanation such as weak evidence, counterfactual instability, or prompt sensitivity. The intended contribution is system-level and diagnostic: we study how much of the observed gain comes from condition separability versus the seven-signal mixture-of-experts (MoE) retention model, rather than claiming that any single signal is a complete mechanistic explanation of bias.

The contributions are as follows:
\begin{itemize}
    \item We identify and quantify a structural property of the original BBQ split: the ambiguous/disambiguated boundary is highly separable from raw context/question representations.
    \item We introduce and audit a deployment-oriented frozen-model selective-abstention policy for BBQ-style multiple-choice question answering that uses predicted, not oracle, condition labels at test time.
    \item We disentangle condition prediction from multi-signal retention, showing that condition-only abstention saturates the clean split while a seven-signal MoE is most useful as a low-label or uncertain-condition fallback.
    \item We add a deterministic explanation layer that reports runtime rationales, signal-based bias-risk explanations, and separate benchmark audit labels for blocked stereotypes, residual bias slips, false abstentions, and utility-preserving keeps.
    \item We provide clean five-seed comparisons against Composite, DeCAP (Debiasing with Context-Adaptive Prompts) \cite{bae2025decap}, and a self-debiasing-style reprompting baseline inspired by \cite{gallegos2024selfdebiasing}, with matched-ID coverage and paired bootstrap reporting.
    \item We add robustness and audit experiments: condition-classifier feature ablations, lexical and encoder-sensitivity checks, Leave-One-Category-Out (LOCO), Open-BBQ transfer, cross-LLM robustness on additional models, threshold and risk-control audits, signal-subset ablations, low-label hybrid audits, residual ambiguous-bias count analysis, and a limited-overlap FairSteer (fairness-steering) appendix check \cite{li2025fairsteer}.
\end{itemize}

The main claim is not that every bias metric is uniformly best or that the MoE is the sole causal driver. Rather, the original BBQ split is unusually condition-separable, and condition-aware selective abstention can maintain high ambiguous abstention accuracy while preserving disambiguated utility under a no-oracle test setting.

The experiments are organized as a decomposition of the final behavior. The primary-answer-only row measures the frozen model's utility before any abstention. Confidence-only and risk-control baselines test whether generic uncertainty is enough. The condition-only rule isolates the effect of predicting the ambiguous/disambiguated boundary. The seven-signal MoE and hybrid variants then test whether additional diagnostic signals help beyond that boundary, especially when condition supervision is scarce.

\section{Related Work}
\label{sec:related}

\subsection{Bias Benchmarks for Question Answering}
BBQ \cite{parrish2022bbq} evaluates social bias in multiple-choice question answering across demographic categories. It is especially useful because it separates ambiguous contexts, where the correct answer is unknown, from disambiguated contexts, where the evidence identifies a target answer. This separation exposes a key failure mode: methods can reduce biased selections by overusing abstention.

\subsection{Dataset Artifacts and Spurious Cues}
Our benchmark-audit framing is related to prior work showing that NLP benchmarks can contain exploitable artifacts. In natural language inference (NLI), hypothesis-only or heuristic-driven behavior can produce inflated scores without the intended reasoning \cite{gururangan2018artifacts,mccoy2019hans}, an instance of the broader shortcut-learning phenomenon \cite{geirhos2020shortcut}. Methodologically, our condition classifier is a partial-input baseline in the sense of \cite{poliak2018hypothesis,kaushik2018reading}, transplanted from gold labels to BBQ's condition variable: it asks how much of the benchmark's intended decision is recoverable without consulting the model under audit. BBQ differs in task and motivation, but the same evaluation lesson applies: high scores should be interpreted alongside audits of what information makes the label predictable. The lexical, encoder-sensitivity, LOCO, and deterministic stress tests in this paper therefore ask whether BBQ improvements reflect robust bias-sensitive reasoning or the easier detection of the ambiguous/disambiguated condition boundary.

\subsection{Prompt-Based and Context-Adaptive Debiasing}
Prompt-based debiasing methods attempt to reduce stereotype-driven outputs using instructions, self-reflection, or generated debiasing prompts. Self-debiasing \cite{gallegos2024selfdebiasing} uses the model's own zero-shot recognition and correction ability, while DeCAP \cite{bae2025decap} generates context-adaptive debiasing guidance for zero-shot QA. These approaches are attractive because they do not require weight updates, but prompt sensitivity and false abstention remain practical concerns. We use a two-prompt recognition-and-correction baseline inspired by self-debiasing, rather than an official reproduction of the full protocol in \cite{gallegos2024selfdebiasing}. A complementary recent line reduces bias by prompting the model to reason from multiple social perspectives: Multi-Persona Thinking \cite{chen2026mpt} aggregates contrasting-identity and neutral viewpoints through an iterative reasoning process. Our contribution is orthogonal to such routing-by-prompt debiasers: rather than steering the answer through a debiasing prompt, we audit whether the BBQ split rewards condition detection and route through selective abstention, so multi-persona prompting and condition-aware abstention could in principle be composed. An MPT-style single-pass reimplementation is included as a baseline in Table~\ref{tab:main}; on the clean split it attains high ambiguous accuracy only through heavy over-abstention on disambiguated items.

\subsection{Selective Prediction, Abstention, and Calibration}
The proposed override mechanism is related to reject-option classification and selective prediction. Classical reject-option work studies the trade-off between recognition error and rejection probability \cite{chow1970optimum}, while modern selective classification builds abstaining neural classifiers by trading coverage for lower risk \cite{geifman2017selective}. Confidence calibration is also relevant because raw neural confidence scores are often miscalibrated \cite{guo2017calibration}. Our setting differs from standard selective classification because the abstention action has asymmetric semantics: abstention is correct for ambiguous BBQ examples but is an error on disambiguated examples. This motivates condition-aware thresholding rather than a single global confidence cutoff.

More recent selective-prediction work trains explicit rejectors, uses end-to-end selective architectures such as SelectiveNet \cite{geifman2019selectivenet}, estimates uncertainty with ensembles \cite{lakshminarayanan2017deepensembles}, or learns to defer to a human or external expert \cite{mozannar2020defer}. In question answering specifically, selective prediction under domain shift trains a calibrator to decide when a QA model should abstain \cite{kamath2020selective}; our setting differs in that abstention is the \emph{correct} action on one half of the benchmark rather than a coverage cost. In NLP, broad selective-prediction audits have found that stronger methods do not always consistently outperform the simple Maximum Probability (MaxProb) baseline across tasks and shifts \cite{varshney2022selective}. Our study therefore includes confidence-only, risk-coverage, and post-hoc risk-control audits, but we do not implement full retraining-based rejectors because the target deployment setting keeps the LLM frozen and uses saved inference-time signals. Closest to our retention score is learned self-evaluation: ASPIRE \cite{chen2023aspire} adapts a self-evaluation signal that improves selective-prediction ranking. Our MoE retention score is a frozen-model analogue trained on saved inference-time signals rather than a fine-tuned self-evaluation head, and we report risk-coverage and AURC for this ranking in Table~\ref{tab:aurc}. More broadly, recent task-oriented surveys of out-of-distribution detection distinguish training-driven from training-agnostic methods \cite{lu2025ood}; our policy sits in the training-agnostic, frozen-model family, specialized to the bias-specific asymmetry that abstention is correct only on ambiguous items.

Conformal prediction and risk-controlling prediction sets provide black-box procedures for coverage or risk control under calibration assumptions \cite{angelopoulos2021conformal,bates2021riskcontrol}. These methods are relevant deployment alternatives because they can wrap a fixed predictor. In BBQ, however, a global coverage or risk target does not by itself encode that abstention is correct for ambiguous examples but incorrect for disambiguated examples. We therefore include post-hoc risk-control baselines as controls, while treating condition-aware action selection as the central distinction.

\subsection{Representation-Level Signals and Steering}
Activation and representation methods, including dynamic steering approaches such as FairSteer \cite{li2025fairsteer}, aim to identify and intervene on bias-related internal directions. Sparse autoencoders have also become useful interpretability tools for extracting sparse features from LLM activations \cite{bricken2023monosemanticity,he2024llamascope}. Our method uses representation-level signals conservatively: SAE activation is included as one audited feature source, but we do not claim that the SAE signal alone causes the observed improvements. The deployment trade-off is also different: steering methods modify internal activations during generation, whereas our method leaves the frozen LLM unchanged and routes the final answer through an abstention policy.

\subsection{Other Bias Evaluation Benchmarks}
Other benchmarks such as StereoSet \cite{nadeem2021stereoset}, CrowS-Pairs \cite{nangia2020crows}, and WinoGender \cite{rudinger2018gender} evaluate stereotype association or gendered coreference behavior. These datasets are useful external checks, but their task semantics differ from BBQ because they do not always contain an explicit unknown option or the same ambiguous-versus-disambiguated decision boundary. We therefore keep non-BBQ transfer results as robustness evidence rather than the main basis for our claims.

\section{Task and Metrics}
\label{sec:task}

Each example contains a context $x$, question $q$, answer choices $A=\{a_1,a_2,a_3\}$, a gold answer $y$, and a condition $c\in\{\mathrm{ambiguous},\mathrm{disambiguated}\}$. In ambiguous examples, the correct behavior is to choose the unknown option. In disambiguated examples, the correct behavior is to choose the context-supported non-unknown answer.

We report three main metrics. Ambiguous accuracy $\accamb$ is the accuracy on ambiguous examples, where correct behavior is abstention. Disambiguated accuracy $\accdis$ is the accuracy on disambiguated examples, where correct behavior is utility-preserving answer selection. False-abstention rate $\far$ is the fraction of disambiguated examples where the model incorrectly predicts unknown. We also compute residual ambiguous bias scores on non-unknown ambiguous predictions, but we treat them as diagnostic rather than primary because their denominator becomes small when $\accamb$ is near one.

\section{Method}
\label{sec:method}

Fig.~\ref{fig:pipeline} summarizes the proposed pipeline. The base LLM is frozen. For each instance, we first run four prompt views: a vanilla QA prompt, a debiasing instruction prompt, a chain-of-thought prompt, and a fourth view designed as a counterfactual-swap prompt; a post-hoc code audit (Limitations) found that this fourth view rendered the unswapped context in all reported runs, so it functions as a second vanilla view inside $s_6$, while the swap-based signal $s_2$ performs the actual demographic swaps. We then extract seven scalar or low-dimensional signals and a question embedding. The deployable policy first predicts whether the example is ambiguous or disambiguated. A simple condition-only version directly uses that prediction to abstain on ambiguous examples and preserve the primary answer on disambiguated examples. A multi-signal MoE version additionally predicts an answer-retention score before applying condition-specific thresholds.

\subsection{Multi-Prompt Signal Extraction}
Table~\ref{tab:signals} lists the seven audited signals. The signals are intentionally heterogeneous: some check whether the answer is supported by context, some check stability under prompt and demographic perturbations, and some use internal model behavior. Subsequent ablations evaluate whether these signals are necessary on the clean BBQ split.

The signal set is organized around three practical failure modes. Evidence and confidence signals target unsupported or low-certainty answers. Counterfactual, consistency, and prompt sensitivity signals target unstable answers whose prediction changes under small semantic or prompting perturbations. Attention-head and SAE signals provide internal diagnostic features for cases where surface evidence alone may miss stereotype reliance. The method does not require each signal to be independently sufficient; instead, the MoE variant learns a validation-calibrated retention policy from their joint pattern.

For reproducibility, $s_1$ asks the LLM to quote an exact contiguous context span supporting the selected answer; the score is 1.0 for a normalized substring match, 0.5 for token-overlap partial support above the implementation threshold, and 0 otherwise. The $s_5$ head set is frozen before test evaluation by a contrastive attention-to-demographic-token audit: we rank heads by mean attention in raw stereotyped-answer cases minus raw anti-stereotyped-answer cases, and serialize the top 20 in the artifact. For $s_7$, we select the SAE layer by a one-time layer comparison over candidate Llama-Scope layers 12, 15, and 18 on a small comparison sample (scoped in the next paragraph); layer 15 and the union of 56 selected feature indices are then fixed for downstream audits. Both choices are one-time diagnostic feature-selection steps, frozen before final reporting.

MoE, condition-classifier, and threshold choices follow a strict train/validation/test discipline and are frozen before final reporting; test examples are used only once the pipeline and operating thresholds have been fixed. The two internal diagnostics are weaker on this point and we scope them accordingly: the $s_5$ head ranking was computed once on a small contrastive sample of training-split predictions, and the $s_7$ layer/feature choice was made once on a 99-instance comparison sample drawn before the per-seed splits were fixed, so that sample is not disjoint from later test splits. Because both signals enter only as audited diagnostic features, and the ablations in Table~\ref{tab:signal_ablation} show the policy's behavior does not depend on them, we treat them as frozen audit probes rather than tuned components.

\subsection{Condition-Aware Abstention and MoE Retention}
Let $s_i\in\mathbb{R}^7$ be the extracted signal vector for example $i$, and let $e_i$ be a question embedding. A lightweight condition classifier predicts whether the instance is ambiguous or disambiguated. We emphasize an embedding-only classifier; adding the non-text features (the seven signals, a primary-answer one-hot, and a category one-hot) raises mean test condition accuracy only from $0.9961$ to $0.9983$ (a $+0.22$-point residual gain), while signals-only and category-only reach $0.833$ and $0.500$, confirming that the text embedding alone is near-ceiling for condition prediction and that non-text features add essentially nothing. For continuity with the audit suite, the condition-only and predicted-condition rows in Table~\ref{tab:main} use the full-feature classifier; the strictly deployable embedding-only variant is the one costed in Appendix~L and evaluated end-to-end in Table~\ref{tab:single_prompt_low_label} (100\% row: 0.9994/0.8774/0.0741), within 0.002 of the Table~\ref{tab:main} condition-only row on every metric. A four-expert MoE then maps the signal vector to a retention score. The MoE uses the saved scalar signal values directly and does not compute test-set normalization statistics. Instead, each signal is rescaled by a learned per-signal temperature vector $\alpha\in\mathbb{R}^7$, initialized to one and learned jointly with the MoE, giving $\bar{s}_i=\alpha\odot s_i$. The gate uses only the question embedding,
\begin{equation}
    g_i=\mathrm{softmax}\!\left(W_{g,2}\phi(W_{g,1}e_i+b_{g,1})+b_{g,2}\right),
\end{equation}
where $\phi$ is ReLU. Each expert is a one-hidden-layer MLP over the concatenated temperature-scaled signals and embedding,
\begin{equation}
    h_{i,k}=W_{k,2}\phi(W_{k,1}[\bar{s}_i;e_i]+b_{k,1})+b_{k,2},
\end{equation}
and the final retention score is
\begin{equation}
    r_i=\sigma\!\left(\sum_{k=1}^{4}g_{i,k}h_{i,k}\right),
\end{equation}
where $\sigma$ is the logistic sigmoid. In the implementation, the gate hidden size is 64, each expert hidden size is 128, expert dropout is 0.1, and $K=4$ experts are used. If $r_i$ falls below a condition-specific threshold, the answer is overridden to unknown; otherwise the original selected answer is retained. The deployable setting uses the predicted condition, while the oracle condition provides a comparable upper-bound estimate that is nearly identical on the clean split. Fig.~\ref{fig:moe} visualizes the separation between expert inputs, gate weights, and the weighted-sum retention score.

We also evaluate a condition-only retention rule:
\begin{equation}
    \tilde{y}_i =
    \begin{cases}
    \mathrm{unknown}, & \hat{c}_i=\mathrm{ambiguous},\\
    \hat{y}_i, & \hat{c}_i=\mathrm{disambiguated},
    \end{cases}
\end{equation}
where $\hat{c}_i$ is the predicted condition, $\hat{y}_i$ is the primary answer from the frozen LLM, and $\tilde{y}_i$ is the final answer emitted after the override. This rule is intentionally simple. It tests whether the benchmark's ambiguous/disambiguated boundary is sufficiently encoded in the available features to explain the main gains without relying on the MoE retention score.

The MoE is trained to estimate whether the primary answer should be retained. For example $i$, the target is $z_i=\mathbf{1}[\hat{y}_i=y_i]$, where $\hat{y}_i$ is the original selected answer before override. The training objective combines binary cross-entropy on $z_i$, a bias penalty that discourages retaining stereotyped non-unknown answers in ambiguous contexts, and a load-balancing term that discourages expert collapse:
\begin{equation}
    \mathcal{L}=\mathcal{L}_{BCE}+\lambda_{bias}\mathcal{L}_{bias}+\lambda_{lb}\mathcal{L}_{lb}.
\end{equation}
The terms are
\begin{equation}
    \mathcal{L}_{BCE}=-\frac{1}{n}\sum_i z_i\log r_i+(1-z_i)\log(1-r_i),
\end{equation}
\begin{equation}
\begin{aligned}
    \mathcal{L}_{bias}
    &=\frac{\sum_i m_i[-\log(1-r_i)]}{\sum_i m_i+\epsilon},\\
    m_i
    &=\mathbf{1}[c_i=\mathrm{ambig}]\\
    &\quad{}\times
      \mathbf{1}[\hat{y}_i\in\mathcal{Y}_{stereo}(i)] .
\end{aligned}
\end{equation}
where $\mathcal{Y}_{stereo}(i)$ is the BBQ metadata-defined stereotyped non-unknown answer set for example $i$. Thus, the second indicator is active only when the raw primary answer selects a stereotyped option in an ambiguous context. The final term is
\begin{equation}
    \mathcal{L}_{lb}=K\sum_{k=1}^{K}\left(\frac{1}{n}\sum_i g_{i,k}-\frac{1}{K}\right)^2.
\end{equation}
The bias penalty therefore affects only ambiguous examples where the raw retained answer maps to a stereotyped non-unknown choice under BBQ metadata; it pushes $r_i$ downward so that thresholding is more likely to abstain. In the clean experiments, the default weights are $\lambda_{bias}=0.5$ and $\lambda_{lb}=0.1$, selected on validation behavior and then frozen before test reporting. Because the clean-split conclusion is driven by the condition-only policy rather than by MoE improvements, we treat $\lambda_{bias}$ as an MoE diagnostic hyperparameter rather than as the source of the main result. Thresholds are selected only on validation data. The oracle-condition thresholds are included as a near-identical upper-bound reference; the main deployable variant applies the same thresholding rule with predicted conditions.

\subsection{Hybrid Fallback and Rule-Based Explanations}
The clean split shows that condition-only abstention is already close to a ceiling. We therefore use the seven-signal retention model as an optional fallback rather than treating it as universally necessary. The hybrid policy first checks the condition classifier confidence, defined as the maximum of the two class probabilities for ambiguous and disambiguated. A confidence threshold and a MoE risk threshold are selected only on validation data by grid search over confidence values from 0.50 to 0.95 and retention-risk thresholds from 0.00 to 1.00. The validation objective maximizes mean ambiguous/disambiguated accuracy, then breaks ties by lower FAR and higher ambiguous accuracy. If confidence is above the selected threshold, the condition-only rule is used; otherwise, the policy falls back to the MoE retention score. This design tests whether the additional signals help most when condition prediction is weak, rather than forcing them into every decision.

We also generate deterministic explanations for each final decision. Runtime explanations use only deployable information: the predicted condition, the retained or overridden answer, and thresholded signal flags such as weak context evidence, counterfactual instability, low choice confidence, prompt sensitivity, high demographic attention, or active SAE bias features. The same runtime inputs are converted into a coarse bias-risk level and a natural-language bias-risk explanation. For example, if the condition predictor marks an item ambiguous and the raw answer is a specific non-unknown option, the explanation states that retaining it would turn an ambiguous context into a specific claim; if $s_2$ or $s_6$ fires, it adds that the answer changes under counterfactual group substitution or prompt views. Separately, benchmark audit explanations use gold BBQ metadata after evaluation to label decision types such as blocked stereotyped raw answer, residual bias slip, false abstention, or utility-preserving keep. This separation avoids using gold labels at deployment while still making the benchmark behavior inspectable.

\section{Experimental Setup}
\label{sec:setup}

\subsection{Models and Data}
The main experiments use Llama-3.1-8B \cite{meta2024llama31} on BBQ. Robustness experiments use Qwen-2.5-7B \cite{yang2024qwen25} and Mistral-7B-v0.3, with Mistral cited through the Mistral 7B technical report \cite{jiang2023mistral}. The clean main evaluation uses five seeds, 42, 123, 456, 789, and 999, with matched test IDs where possible.

The saved-signal pool contains 8,864 examples drawn from the full BBQ release by per-category stratified sampling balanced over context conditions (approximately one thousand examples per category with a fixed seed; \path{src/utils/data_loader.py}). For each clean seed, this pool is split into 6,208 training examples, 1,328 validation examples, and 1,328 test examples; a separate fixed held-out split of 1,332 examples is used for single-pass rows such as the MPT-style baseline. Throughout, $\pm$ denotes the standard deviation over the five seed-level values. Because the five seeds re-split one shared pool, any two test splits overlap on 13.5--15.9\% of instances (mean 14.7\%); the $\pm$ values therefore quantify split-resampling variability rather than fully independent replication, and pooled seed-level counts (e.g., 6{,}640 decisions) count recurring instances more than once. Question/context embeddings use \texttt{sentence-transformers/all-MiniLM-L6-v2} unless otherwise noted. We use MiniLM as the default because it is a lightweight sentence encoder suitable for the intended frozen inference-time setting; Appendix~\ref{app:condition_audit} adds encoder-sensitivity checks to avoid making the separability claim depend on one encoder. We do not treat the direct English-to-KoBBQ~\cite{jin2024kobbq} result as a multilingual claim because the same English-trained embedding classifier fails under Korean transfer; multilingual encoders are therefore a future transfer direction rather than a current result. The MoE is trained for 30 epochs with batch size 32, AdamW, learning rate $10^{-3}$, weight decay $10^{-5}$, gradient clipping at 1.0, and best-checkpoint selection by validation loss. The condition classifier is a balanced logistic-regression model over category, primary-answer, embedding, and signal features; the primary-answer feature is the model's selected answer, not the gold answer. Its mean clean test accuracy across the five seeds is 0.9983, so the predicted-condition and oracle-condition variants are expected to be close on the main BBQ split. Appendix~\ref{app:condition_audit} shows that removing the primary-answer feature barely changes this result, while embedding-only prediction remains strong. LOCO is reported separately because condition prediction is harder when a category is held out.

The embedding-only condition classifier uses only the raw context and question text encoded by the sentence-transformer model; it does not use answer choices, category labels, model outputs, or any of the seven extracted signals. This audit directly tests whether condition prediction depends on answer leakage or model-output coupling.

We tune thresholds on the validation split rather than the test split. The single-threshold variant searches one retention threshold over a grid, while the condition-aware variants search separate ambiguous and disambiguated thresholds on validation data. The final reported test metrics are then computed once on the held-out test split.

\subsection{Baselines}
We compare against a Composite prompt-only baseline, DeCAP \cite{bae2025decap}, a self-debiasing-style reprompting baseline (SDR), a primary-answer-only audit baseline, the condition-only retention rule, a single-threshold version of the MoE, and the full predicted-condition MoE. SDR follows the recognition-and-correction idea of \cite{gallegos2024selfdebiasing}; our reprompting is an unofficial reimplementation rather than a tuned reproduction of all prompt variants in the original work. We additionally report an MPT-style multi-persona prompting baseline following \cite{chen2026mpt}: the model reasons from each named group's perspective plus a neutral viewpoint before answering, with the unknown option available; this is likewise an unofficial single-prompt reimplementation rather than the authors' full iterative protocol, and is run as a single deterministic pass over the held-out test split. Because the SDR baseline over-abstains heavily, we treat it as an auxiliary replication note rather than a primary claim. This limits the strength of any conclusion about self-debiasing as a family of methods, but it does not affect the main decomposition between condition-only, confidence-only, and MoE retention. FairSteer is reported only as a limited-overlap auxiliary comparison because the matched-ID overlap is small, with approximately 15 examples per seed.

\subsection{Statistical Testing and Audits}
For main comparisons, we use paired bootstrap tests on matched IDs. We use Bonferroni correction because the baseline-metric comparisons are not fully independent and a conservative threshold is preferable for the main claims. We also report LOCO generalization, Open-BBQ zero-shot transfer, cross-LLM robustness, cross-backbone condition-classifier transfer, low-threshold audits, condition-classifier ablations, lexical and encoder-sensitivity condition audits, post-hoc and condition-aware risk-control baselines, deterministic paraphrase-stress data, signal-subset ablations, low-label hybrid fallback audits, rule-based explanation audits, and residual ambiguous-bias counts. These analyses test whether the observed gains are driven by category memorization, split overfitting, threshold artifacts, condition-label separability, unstable residual-bias metrics, or a lack of auditable decision rationales.

\subsection{Main Clean BBQ Comparison}
Table~\ref{tab:main} shows the clean five-seed BBQ results. The strongest deployable result on the main split is the condition-only retention rule, which achieves $\accamb=1.0000\pm0.0000$, $\accdis=0.8789\pm0.0070$, and $\far=0.0726\pm0.0067$. The full seven-signal MoE predicted-condition variant remains strong at $\accamb=0.9946\pm0.0054$, $\accdis=0.8732\pm0.0108$, and $\far=0.0843\pm0.0193$, but it is not the simplest or strongest explanation of the main-split gain. A separately audited hybrid fallback reaches $\accamb=0.9979\pm0.0020$, $\accdis=0.8795\pm0.0070$, and $\far=0.0723\pm0.0071$ when full condition supervision is available, indicating that its main advantage is not the already-easy clean split but the low-label setting analyzed below. Under the template-disjoint split (Appendix~\ref{app:condition_audit}), the condition-only operating point degrades to $\accamb=0.9319$, $\accdis=0.7993$, and $\far=0.1480$; we regard this, rather than the clean-split frontier, as the more deployment-relevant estimate.

The primary-answer-only audit is also important: it already reaches $\accdis=0.8798$ and $\far=0.0717$, so the main clean-split gain comes mainly from improving ambiguous abstention while preserving disambiguated utility. The policy converts unsupported ambiguous-context answers into the correct unknown option while preserving, rather than improving, the base model's disambiguated utility. Compared with Composite and DeCAP, the condition-aware policies improve ambiguous accuracy and disambiguated utility while reducing false abstention. One parsing-convention caveat applies to the Composite row only: 14.9\% of its chain-of-thought responses remain unparseable even under the corrected parser and score as wrong by convention, whereas DeCAP, SDR, and MPT parse at a 0.0 failure rate, so the convention penalizes no baseline except Composite (see Limitations). Compared with SDR, they avoid severe over-abstention on disambiguated examples. The MPT-style multi-persona baseline shows the same failure mode in a milder form: it reaches $0.9565$ ambiguous accuracy, close to the condition-aware policies, but only by abstaining on two thirds of disambiguated examples ($\far=0.6667$, $\accdis=0.3003$). This reinforces the central decomposition: perspective-diverse prompting buys ambiguous safety through indiscriminate abstention, whereas condition-aware abstention achieves the same ambiguous accuracy while preserving disambiguated utility.

\subsection{When the Signal Fallback Helps}
The clean main split makes condition prediction unusually easy, so the condition-only rule is difficult to improve. To test whether the seven-signal fallback is useful under weaker supervision, we retrain the condition classifier with only a fraction of the condition-labeled training examples and keep the same validation-only hybrid tuning procedure. Table~\ref{tab:low_label_hybrid} shows that the hybrid fallback is most valuable when condition supervision is scarce, especially at 1--5\% labels. With only 1\% of condition labels, the hybrid improves $\accamb$ from 0.9136 to 0.9530, $\accdis$ from 0.6786 to 0.8247, and reduces $\far$ from 0.2931 to 0.1452. A paired example-level bootstrap (10{,}000 resamples per seed, reconstructed with the audited per-seed gating thresholds and saved retention scores; reconstruction matches the original seed means within $0.01$--$0.04$) confirms the claim inferentially: at 1\% labels the hybrid-vs-condition-only deltas are significant for all three metrics in every seed (maximum two-sided $p<10^{-4}$, far below the Bonferroni threshold $0.05/9=0.0056$); at 5\% the $\accdis$ and FAR gains remain significant in every seed; by 10\% only the $\accdis$ gain is uniformly significant, consistent with the fallback narrative. It also reduces seed-level variance in $\accdis$ from 0.0674 to 0.0313. One supervision-accounting caveat applies: the label fraction varies only the \emph{condition classifier}, while the MoE retention model (including the bias penalty of Eq.~7) was trained once on the full training split using gold answers, which in BBQ largely encode the condition. The quoted budgets ($\approx$62 labels at 1\%) therefore count explicit condition annotations only, and the hybrid's fallback inherits a fixed, fully supervised retention model; the claim is that condition \emph{annotation} can be scarce given a pretrained retention score, not that the entire system trains from 62 labels. By 10\% and 100\% labels, the hybrid provides only marginal $\accdis$ or FAR gains and can slightly reduce $\accamb$ (0.9852 to 0.9834 at 10\%; 1.0000 to 0.9979 at 100\%). This is consistent with the framing that signals are a low-supervision fallback rather than a main-split mechanism.

\subsection{Generalization Beyond the Main Split}
Table~\ref{tab:generalization} reports generalization and robustness experiments. In LOCO, each BBQ category is held out from training and used for evaluation. The predicted-condition variant remains strong, with $\accamb=0.9214\pm0.0421$, $\accdis=0.8331\pm0.0793$, and $\far=0.1161\pm0.0551$ across 45 folds. This supports the interpretation that the method is not merely memorizing category-specific patterns.

Open-BBQ transfer provides an external BBQ-style check; it is converted from the publicly released Open-BBQ benchmark of \cite{openbias2025} (eleven categories including two intersectional ones); our conversion script and the converted files are part of the released artifact. The transfer MoE rows in Table~\ref{tab:generalization} were produced with the pipeline's inherited gold-condition routing; to resolve the routing convention explicitly, we reconstructed the same rows from the saved signals and runtime embeddings under deployable predicted-condition routing. On 3,300 Open-BBQ examples, gold routing achieves $\accamb=0.9915$, $\accdis=0.8358$, and $\far=0.1012$, and predicted-condition routing $0.9855$/$0.8315$/$0.1061$ (condition agreement 0.978), so the routing convention shifts each metric by at most 0.006; the table reports both rows. Cross-LLM experiments show the same qualitative pattern on Qwen and Mistral, though with higher false-abstention rates than Llama. For Qwen and Mistral, no compatible public SAE feature set was used; the $s_7$ field is therefore zero/default in those runs, which may contribute to the weaker FAR relative to Llama. Appendix~\ref{app:condition_audit} further audits KoBBQ condition prediction. KoBBQ itself is highly separable when trained and tested within KoBBQ (0.9995 full-feature accuracy), but an English-BBQ-trained embedding classifier does not transfer directly to Korean examples (0.5000 full-feature transfer accuracy). This dissociates benchmark structure from transferred representation: the KoBBQ end-to-end drop is better interpreted as cross-lingual representation and policy-transfer failure than as evidence against condition-aware abstention itself. Table~\ref{tab:generalization} therefore surfaces the two hardest transfer rows in the main text rather than only in the appendix: on our author-generated implicit-cue paraphrase set the policy falls to $\accamb=0.8227$, $\accdis=0.5464$, $\far=0.3208$ (gold-condition routing; the deployable predicted-condition figure is plausibly lower), and on KoBBQ end-to-end to $0.6557$/$0.6475$/$0.2186$. These numbers bound the deployment envelope: when the condition boundary is no longer visible in surface form (implicit cues) or the encoder is out of language, condition-aware abstention degrades materially, which is exactly what the audit framing predicts.

We also run two follow-up stress audits requested by reviewers. First, a deterministic entity-masking/light-rewrite BBQ stress file removes or weakens some demographic and template cues while preserving original condition labels; an English-BBQ-trained embedding-only condition classifier drops from 0.9961 on the clean split to 0.9373 accuracy on 8,100 generated stress examples (an optimistic bound, since the stress set includes rewritten variants of classifier-training instances; the template-disjoint control below gives the uncontaminated 0.8874). This supports the concern that lexical/template cues help the clean split, but also shows that condition information is not erased by the deterministic rewrites. Second, when a Llama-trained condition classifier is evaluated on Qwen or Mistral saved records, embedding-only transfer remains strong (0.9961 condition accuracy), whereas signal/primary-answer feature transfer collapses toward chance. Thus, text-level condition separability transfers across backbones, but model-output and signal distributions are backbone-specific.

\subsection{Rule-Based Explanation Audit}
The explanation layer---more precisely a deterministic decision-trace layer, since its outputs are rule-generated audit rationales rather than validated cognitive explanations---converts each final decision into a deterministic runtime rationale, a signal-based bias-risk explanation, and a separate benchmark audit label. Across the five clean test splits for the predicted-condition variant, it identifies 1{,}035 cases where a raw stereotyped answer in an ambiguous context was blocked by abstention, 409 cases where a raw anti-stereotyped but still unsupported answer was blocked, and only 10 residual stereotyped bias slips out of 6,640 seed-level decisions (direction labels use the corrected group matcher described in the Limitations section). It also separates 280 false abstentions from 2,899 utility-preserving disambiguated keeps. The deployable bias-risk artifact labels 1,464 decisions as high risk, 692 as moderate risk, 4,200 as low risk, and 282 as utility-risk over-abstentions. These counts are not an additional accuracy metric, but they make the decision behavior easier to inspect and help prevent overstating the SAE or MoE components as causal explanations. On the retained side, the 77 wrong stereotyped keeps versus 64 wrong anti-stereotyped keeps show no significant direction skew (two-sided binomial $p=0.31$; the most affected categories are Religion at 17:11 and Physical appearance at 12:15). Of the 1{,}464 high-risk labels, 1{,}461 coincide with blocked-stereotyped, blocked-unsupported, or slip outcomes under the gold audit labels, and only 3 fire on benign outcomes (2 false abstentions, 1 utility-preserving keep); this 99.8\% coincidence is partly definitional, since the risk rules and the audit taxonomy condition on the same abstention decision, so it should be read as internal consistency rather than external validation. The released rationale artifacts carry an explicit rule-derived, not-human-verified disclaimer field. Appendix~\ref{app:explanations} reports the full decision taxonomy and the bias-risk summary.

The residual failures are not uniformly distributed across categories. The over-abstentions and wrong disambiguated keeps concentrate in Physical appearance, the category with the highest per-category false-abstention rate (Table~\ref{tab:category_coverage}, $\far=0.179$), followed by Religion ($\far=0.123$); by contrast Race ethnicity, Nationality, and Socioeconomic status have the lowest. This is the qualitative counterpart of the aggregate FAR disparity and indicates where validation-only category-aware calibration (Table~\ref{tab:category_calibration_followup}) would help most. The disparity widens under shift: the worst-category FAR reaches 0.433 (Disability status) on the implicit-cue set and 0.327 on the Qwen backbone (Appendix~J), so aggregate FAR is not a sufficient deployment criterion and per-category coverage monitoring is a required component of the deployable policy, not an optional audit.

Representative decisions illustrate the taxonomy. In an ambiguous Disability example, the raw answer selects a stereotyped non-unknown option; the policy marks the context ambiguous and overrides to unknown, blocking the stereotype. In a disambiguated Age example, the raw answer matches the gold label and is retained, preserving utility. The ten residual stereotype slips out of 6{,}640 seed-level decisions are ambiguous cases where the retention rule kept a specific answer whose signals appeared benign---high choice confidence and cross-sample consistency---so the multi-signal layer did not flag them. This is consistent with the small single-signal masking deltas in Table~\ref{tab:signal_ablation} and reinforces that condition prediction, not the auxiliary signals, drives the clean-split behavior. A token-level view of one such ambiguous case (Figure~\ref{fig:token_signals}) makes this concrete: the bias-head attention falls on structural tokens rather than the demographic words, and the SAE feature activates diffusely.

The deterministic explanations are faithful to the signals that actually fired: each runtime rationale and bias-risk level is generated only from the deployable predicted condition, answer type, and thresholded signal flags, so the explanation reflects the same flags used by the decision rather than a post-hoc narrative. We note that the SAE bias-feature flag is active across both correct and incorrect decisions, so it has limited standalone discriminative value; accordingly the explanations report it as an audit signal rather than a causal cause, consistent with our treatment of $s_7$.

\subsection{Residual Ambiguous Bias}
Residual ambiguous-bias scores for the predicted-condition variant are numerically unstable and should not be used for ranking. This happens because ambiguous accuracy is near perfect: across the five clean seeds, the residual non-unknown ambiguous counts are only 0, 1, 3, 5, and 9, pooling to 10 stereotyped versus 8 anti-stereotyped residuals under the corrected group matcher, with per-seed direction scores swinging from $-1$ to $+1$. Therefore, the denominator for a residual stereotype-vs-anti-stereotype score is too small for a strong ``lowest bias score'' claim. We report raw counts and confidence intervals in the appendix and use $\accamb$, $\accdis$, and $\far$ as the main comparison metrics.

\section{Discussion}
\label{sec:discussion}

The central result is a favorable utility-abstention trade-off produced by condition-aware selective abstention. The clean-split contribution is asymmetric. The primary-answer-only baseline already performs well on disambiguated examples, so the selective policy mainly improves ambiguous-context behavior while preserving disambiguated utility. This is still practically important because a system that answers ambiguous examples with demographic guesses can look useful while failing the intended benchmark semantics. At the same time, the audit shows that the original BBQ split makes condition prediction unusually easy. The predicted-condition and oracle-condition variants are nearly identical because the ambiguous/disambiguated boundary is strongly encoded in embeddings and related surface features, not because the system secretly uses oracle labels.

The new lexical and encoder-sensitivity controls make this conclusion sharper. If word n-gram and character n-gram classifiers can recover the condition boundary, then the clean split is not merely separable in one neural embedding space; it also carries template-level cues. Conversely, the post-hoc risk-control baselines show that generic confidence calibration does not reproduce the same utility-abstention balance. A stronger condition-aware risk-control wrapper can approach the condition-only operating point when it uses the predicted condition partition, but it still does not improve on the simple rule. Together, these controls support the benchmark-audit framing: clean BBQ rewards detecting the condition boundary, and that boundary is unusually visible.

The auxiliary experiments also clarify what should not be overclaimed. FairSteer is not a main baseline in our analysis because the matched-ID overlap is too small. The SAE signal is included and audited, but the ablation does not justify claiming that SAE feature $s_7$ is the main reason for the improvement. The MoE itself is also not the most parsimonious explanation on the clean main split, since the condition-only retention rule performs at least as well. Similarly, residual ambiguous-bias scores should be interpreted with raw residual counts because near-perfect ambiguous abstention leaves too few non-unknown cases for a stable score.

\subsection{Novelty and Scope}
The novelty claim is intentionally framed as a deployable decision analysis rather than as a single new representation primitive. The method combines condition prediction, heterogeneous signal extraction, optional MoE retention, condition-specific thresholding, and deterministic decision explanations into a no-oracle inference-time abstention policy. This scope matters for evaluation: the relevant question is whether condition-aware abstention improves the utility-abstention trade-off while remaining robust to category holdout, transfer, and backbone changes, and whether the resulting decisions can be audited after the fact. We do not claim universal bias mitigation across all fairness datasets, a causal mechanistic proof for any individual signal, or that the seven-signal MoE is necessary on the original BBQ split. Concretely, the contribution is diagnostic, in the spirit of benchmark-artifact audits in natural language inference and reading comprehension: showing that a benchmark's headline metric is largely explained by an easily detectable structural property is itself a result, independent of whether a more elaborate model improves that metric. The limited clean-split benefit of the MoE is therefore reported as a finding rather than a shortcoming, and the multi-signal layer is retained because it is the component that helps in the low-label and uncertain-condition regimes where the condition-only rule degrades. Relative to prior work, the increments are threefold: (i)~abstention with asymmetric, condition-dependent semantics, where abstaining is the correct action on half the benchmark rather than a uniform coverage cost (unlike standard selective classification \cite{geifman2017selective,kamath2020selective}); (ii)~evidence that generic confidence thresholds and learned rejectors over the same features do not recover the condition-aware operating point, while a two-line condition rule does; and (iii)~a quantified decomposition of where BBQ condition separability comes from---length features alone $0.948$, lexical n-grams $0.997$, sentence embeddings $0.996$, dropping to $0.887$ under a template-disjoint split and $0.891$ under category holdout---turning an implicit benchmark property into measured boundary conditions.

The explanation layer should be interpreted in the same audit-oriented spirit. It is not a substitute for a human study of explanation usefulness. Its purpose is to produce deterministic, reproducible labels and signal-based bias-risk reasons for why a decision was kept or overridden, so that residual slips, false abstentions, and blocked raw stereotypes can be inspected without asking the model to generate post-hoc rationales.

\section{Limitations}
\label{sec:limitations}

First, the method is designed for BBQ-style multiple-choice question answering with an explicit unknown option. Transfer to free-form QA or tasks with different output semantics is less clean. StereoSet, WinoGender, and KoBBQ results are informative but mixed, and should be treated as appendix robustness checks rather than main evidence. Second, the policy assumes at least a small amount of condition-labeled calibration data. The 1--5\% low-label experiments simulate a small annotation budget, but they do not prove that weak supervision or automatically generated condition labels would be reliable in a new deployment. A practical deployment would need a labeled calibration set, periodic drift checks, and a rule for abstaining or deferring when the condition classifier is uncertain. Third, the clean BBQ split is highly condition-separable, so results on that split should be interpreted partly as an audit of the benchmark structure. LOCO lowers condition-prediction accuracy, and KoBBQ shows that condition separability can be strong within a new language while still failing under direct English-to-Korean embedding transfer; replacing the English-centric encoder with a multilingual one largely restores this transfer: a LaBSE condition classifier trained on English BBQ reaches $0.977$ condition accuracy on KoBBQ and multilingual-E5 reaches $0.885$, versus $0.493$ (near chance) for the default all-MiniLM encoder, while within-KoBBQ condition accuracy stays near $1.0$ for all three encoders. The lexical n-gram audit and deterministic entity-masked stress set further suggest that simple template or wording cues explain part, but not all, of the clean-split separability; a human-verified paraphrase or adversarial BBQ benchmark remains necessary before treating this as general semantic robustness. Fourth, the full multi-signal pipeline is more expensive than single-prompt question answering because it uses four prompt views plus additional evidence, counterfactual, and consistency probes. The clean-split condition-only policy is much cheaper: it needs the primary answer and a sentence embedding for context/question text, while the seven-signal layer is best reserved for low-label or uncertain-condition settings. We report prompt-equivalent cost rather than hardware-specific wall-clock latency: condition-only uses one primary prompt plus one embedding pass, while the full signal pipeline uses the primary prompt, three additional prompt views (including the intended swap view; see the audit disclosure below), an evidence call, the $s_2$ counterfactual call, and consistency samples. Fifth, per-category FAR differences remain. We report category-level coverage and a validation-only category-calibration audit, but we do not use group-specific thresholds in the main policy because a group-aware deployment rule requires an explicit fairness objective and validation protocol. Sixth, the internal attention-head and SAE signals are diagnostic and should not be interpreted as full mechanistic explanations. Seventh, the rule-based explanations are deterministic audit rationales, not human-validated causal explanations of model cognition; we do not conduct a user study testing whether these rationales improve trust or debugging efficacy; as future work we plan a small auditor pilot measuring whether the signal-based bias-risk rationales improve error triage and trust calibration. Eighth, we evaluate confidence-only baselines, post-hoc and condition-aware risk-control baselines, and simple logistic rejectors over the same extracted features, but we do not implement heavy retraining-based selective classifiers, deep ensembles, or human-expert deferral systems, which are outside the frozen-LLM inference-time setting. Ninth, all evaluation is automatic and benchmark-based; human-centered fairness evaluation remains necessary before deployment in real-world decision-support settings.

Finally, a post-hoc audit of the released code identified five implementation defects, which we disclose for reproducibility; none affects the primary $\accamb$/$\accdis$/$\far$ metrics. (i) The stereotype-direction audit originally matched BBQ answer-group tags against the stereotyped-group metadata by exact string equality, which fails for roughly a third of instances (e.g., \texttt{lowSES} vs.\ ``low SES'', gender-prefixed race tags, region tags vs.\ nationality demonyms) and silently falls back to question polarity. All direction-dependent counts in Section~VI and the appendices were recomputed with a normalized matcher (near-100\% tag coverage), and this paper reports the corrected numbers; primary metrics never use direction labels and are unchanged. One training-side consequence remains: the MoE bias penalty of Eq.~7 was trained with the pre-correction direction labels, so for roughly a third of instances its target degenerated to question polarity; all reported MoE results evaluate that trained checkpoint as-is, which is consistent with treating $\lambda_{bias}$ as a diagnostic hyperparameter rather than the source of the main result. Rebuilding the Eq.~7 labels with the corrected matcher (11.2\% of labels change) and retraining the MoE together with the corrected $s_5$/$s_7$ signals of item~(iii) gives $\accamb$ $0.9937\pm0.0073$, $\accdis$ $0.8753\pm0.0098$, $\far$ $0.0822\pm0.0157$---within 0.003 of the reported row---so the MoE-null conclusion also holds under the fully corrected training pipeline. (ii) The fourth prompt view did not perform its intended demographic swap (it re-rendered the original context), so $s_6$ measures instruction-paraphrase sensitivity only; the swap-based signal $s_2$ is unaffected. (iii) The $s_5$ extraction reads attention at a one-token offset from the demographic mention and matches only single-token mentions, and the $s_7$ hook reads the residual stream one layer below the nominal SAE layer; both signals are therefore noisier than designed, which is consistent with their near-zero ablation deltas, and we treat them strictly as audit probes. To confirm this, we re-extracted both signals with corrected code (offset-mapping token matching, which eliminates the 0--69\% per-category zero rates of the original $s_5$; the correct SAE layer for $s_7$) over the full pool and re-trained the MoE and the masking ablation on the corrected signals: the main operating point moves by at most 0.004 ($\accamb$ $0.9943\pm0.0046$, $\accdis$ $0.8753\pm0.0095$, $\far$ $0.0810\pm0.0147$), the $s_5$/$s_7$ masking deltas remain below 0.003 in absolute value, and no conclusion changes; the corrected extractions are released alongside the originals. (iv) The chat-template wrapper prepends a duplicate beginning-of-sequence token to every prompt; all reported runs share this convention, so comparisons remain internally consistent. (v) The chain-of-thought answer parser could misread responses such as ``Answer: Based on \ldots'' (taking the spurious ``B''); the Composite baseline was re-scored from saved raw responses with a corrected parser, which raised its ambiguous accuracy from 0.684 to 0.718 and changed no conclusion (1{,}318 of its 8{,}864 responses, 14.9\%, remain unparseable even under the corrected parser and score as wrong, the standard convention). The corrected code and all recomputation scripts are tagged \texttt{v1.0.2} in the released repository; \texttt{v1.0.2} supersedes \texttt{v1.0.1}, additionally containing the corrected $s_5$/$s_7$ extraction code and artifacts, the transfer-routing reconstruction, and the template-disjoint split export.

\section{Conclusion}
\label{sec:conclusion}

This paper presented \method{}, a frozen-model policy and audit for bias-sensitive question answering with no-oracle condition-aware abstention. On clean BBQ evaluations, condition-aware retention converts unsupported ambiguous-context answers to unknown while preserving disambiguated utility. The strongest conclusion is that BBQ-style bias evaluation rewards condition-aware selective abstention more than fine-grained multi-signal retention on the original split, and that this behavior reflects a structural property of the benchmark. Within this picture, the seven-signal layer is best understood as a low-label fallback rather than a main-split mechanism: under 1\% condition supervision it improves disambiguated accuracy from 0.6786 to 0.8247, while contributing little when condition prediction is already near-perfect. The rule-based explanation artifacts make blocked stereotypes, residual slips, false abstentions, utility-preserving keeps, and signal-based bias-risk reasons inspectable without relying on free-form rationales. LOCO, Open-BBQ transfer, deterministic paraphrase stress, KoBBQ condition-transfer audits, condition-aware risk-control baselines, and cross-LLM experiments provide additional evidence beyond the main split, while residual bias scores, SAE-feature interpretations, and MoE-causality claims should be reported cautiously.

\auditappendixsection{Per-Category Coverage Audit}{app:category_coverage}
Table~\ref{tab:category_coverage} reports condition-only retention coverage by BBQ category. Overall coverage is near one half because the split contains equal ambiguous and disambiguated examples and the intended behavior is to abstain on ambiguous contexts. The more relevant disparity check is therefore disambiguated coverage, equal to $1-\far$. Physical appearance and Religion have the largest FAR values, while Race ethnicity, Nationality, and Socioeconomic status (SES) have the lowest. We do not use category-aware thresholds in the main results because they would introduce group-specific deployment policy choices; validation-only category calibration is a useful mitigation direction once a fairness objective is specified. In our validation-only audit (Table~\ref{tab:category_calibration_followup}), per-category thresholds reduce aggregate FAR only marginally ($0.0726\rightarrow0.0717$) while lowering condition accuracy ($0.9983\rightarrow0.9928$), so we treat per-category or per-template calibration---which would target the Physical appearance ($\far{=}0.179$) and Religion ($\far{=}0.123$) gap---as a deployment option that should be tied to an explicit fairness objective rather than enabled by default. A natural such objective is an equalized false-abstention rate across groups; the validation-only audit suggests it would trade a small ambiguous-accuracy reduction (the category-aware row lowers $\accamb$ from $1.0000$ to $0.9946$) for reduced per-category FAR disparity, which we leave to a fairness-objective-driven deployment study. A complementary per-category audit explains why threshold calibration alone is insufficient: recomputing per-category FAR under per-category condition thresholds leaves the profile essentially unchanged (Physical appearance remains at $0.179$; the max--min spread moves from $0.152$ to $0.157$), because the disparity is driven by the frozen model's own unknown answers on disambiguated items rather than by condition-boundary placement. Closing the gap therefore requires category-aware retention thresholds or intervention on the base model, not condition-classifier calibration. The disparity is also not stable under shift: on the implicit-cue paraphrase set the per-category FAR spread widens from $0.152$ to $0.222$ and the worst-affected category changes from Physical appearance to Disability status ($0.433$, with Religion at $0.403$), and on the Qwen backbone (Open-BBQ transfer) the spread is $0.240$ with Disability status and Physical appearance worst at $0.327$. Whoever bears the abstention burden therefore depends on the distribution and backbone, which strengthens the case for monitoring per-category coverage in deployment rather than fixing one calibration. \auditappendixsection{Signal Implementation Details and Inference Cost}{app:signal_impl}
\textbf{Evidence ($s_1$).} Under a verbatim-extraction system prompt, the model is asked to quote the exact contiguous context span supporting its selected answer, or to output \texttt{NONE} if no explicit support exists; decoding is greedy ($T{=}0$, $\le 96$ tokens). The returned text is parsed in priority order (a triple-quoted span, then a quoted substring, then the first line) and scored against the context after normalization (lowercasing, whitespace collapse, punctuation removal): the score is $1.0$ if the normalized quote is a substring of the normalized context, $0.5$ if the unigram token-overlap ratio $|q\cap c|/|q|\ge 0.5$, and $0.0$ otherwise (empty output, \texttt{NONE}, or no overlap). Thus $s_1$ is a quote-\emph{grounding} proxy rather than an entailment judgment. Its dominant failure mode is over-quoting: a model can return a long or whole-context span that yields $s_1{=}1.0$ even on an ambiguous item with no genuine evidence (a token-level instance is shown in Fig.~\ref{fig:token_signals}). The decision therefore relies on the condition and MoE layers, not on $s_1$ alone.

\textbf{Counterfactual consistency ($s_2$).} $s_2$ swaps the two non-\texttt{unknown} demographic answer entities in the context and re-queries the frozen model under the same prompt. The entities are the answer-option strings tagged non-\texttt{unknown} in the BBQ \texttt{answer\_info}; the swap is a case-insensitive, word-bounded regular-expression substitution (word boundaries are applied only when the string begins or ends with an alphanumeric character) using a placeholder for a safe three-way exchange, with the answer options, \texttt{answer\_info} tags, and gold label swapped consistently. The signal is $1.0$ if the post-swap answer maps to the same BBQ group tag as the original answer and $0.0$ otherwise---that is, whether the answer follows the demographic \emph{group} rather than the surface position. Three implementation points address the reviewer's question. (i)~Multi-word entities are matched as whole strings, so proper names and full options swap reliably; when the option string differs from its in-context surface form (option ``the Malian friend'' versus context mention ``my Malian friend''), the bounded match can fail and the context is left unchanged, in which case $s_2$ reduces to a same-context re-query. (ii)~The swap is a syntactic entity exchange, not a generative rewrite, so sentence structure and length are preserved by construction; there is no explicit semantic-coherence check, and the procedure relies on the symmetry of BBQ's two-group templates. (iii)~If an instance does not expose exactly two non-\texttt{unknown} groups, $s_2$ is undefined and defaults to $1.0$. Quantitatively, on the 8{,}864-example pool the missing-groups default never fires (0 instances), but in 48.6\% of instances neither option string occurs verbatim in the context, so the swap is a no-op and $s_2$ degenerates to a same-context re-query; because this failure mode is anti-conservative (a matching failure reads as consistency), we flag it here and in the signal table; the released v1.0.x implementations retain the $1.0$ default, and all reported metrics were computed under that convention.

\textbf{Inference cost.} Table~\ref{tab:cost} reports the per-example LLM cost. The full seven-signal pipeline issues eleven generation calls per example---four prompt views (vanilla, debiasing, chain-of-thought, and the intended counterfactual-swap view; see Limitations) that are reused for $s_6$, one evidence call ($s_1$), one counterfactual call ($s_2$), and five self-consistency samples ($s_4$, $T{=}0.7$)---while $s_3$, $s_5$, $s_6$, and $s_7$ add no further generations (log-probabilities, attention maps, reused prompt answers, and a layer-15 SAE forward pass). The deployable condition-only policy instead needs a single primary generation plus one sentence-embedding pass (\texttt{all-MiniLM-L6-v2}). The signal pipeline is therefore roughly an order of magnitude more expensive in generation calls for no clean-split gain, which is why it is reserved for the low-label or uncertain-condition regime. Measured end-to-end on a single H100 SXM GPU (bfloat16, eager attention, batch size 1, HF Transformers; 32-example micro-benchmark), the deployable condition-only policy runs at $0.099$\,s per example (one short-completion call plus a MiniLM embedding pass, both on the same GPU and the same 32-example micro-benchmark; this prices the embedding-only classifier variant of Section~V.A, since the full-feature variant would require the signal pipeline) and the full eleven-call signal pipeline at $2.31$\,s per example; on the same setup the multi-persona chain-of-thought baseline averaged $3.6$\,s per example (256 new tokens, 1{,}332 examples) and the composite chain-of-thought baseline $8.2$\,s per example ($\sim$100 new tokens, 8{,}864 examples). On the labeling-economics side, the hybrid needs only $\approx$62 condition labels at the 1\% fraction but pays the 23$\times$ inference multiplier on every example, whereas $\approx$620 labels (10\%) already bring the cheap condition-only rule within roughly one point of the hybrid; the multi-signal fallback is therefore most economical when labels, not inference, are the binding constraint.
